How the referee works

Three steps, repeated ten times a second, all inside this tab.

  1. 1Find each player

    A pose model spots everyone in front of the camera, up to four players, and puts a box around each one. You keep your number for as long as you stay in view.

  2. 2Measure the movement

    Ten times a second, each box is shrunk to the same small square and compared with the last look: the share of the player that changed is the score. Standing close to the camera doesn't make you look guiltier.

  3. 3Call it on red

    When the light turns red you get a moment to stop. After that, anyone whose score stays over the line for three checks in a row is out. The countdown measures your camera first, so breathing and camera noise stay under it.

Everything happens in this tab. The pose model downloads once, when you press Play; your camera picture is never uploaded, recorded or kept.

Apparent player size

Watch the brightness

Sum the pixels in the player's box and call any change movement. It needs no model and no motion estimate at all, and what it actually tracks is how many pixels the player covers: shrink them and it never fires, bring them closer and it fires on everybody. It flags frozen and moving players at the same rate, which is another way of saying it is a coin flip.

Difference the whole frame

Subtract this frame from the last one and count the pixels that changed. On an empty room it works. Put one frozen player in a street scene and everybody walking past is charged to them: the whole-frame score crosses its cutoff within a second and stays there for half the run, while the same player scored inside their own box reads exactly zero.

Measure flow in raw pixels

Estimate optical flow inside the box and threshold the raw pixel speed. This one is nearly right, and it fails quietly: pixels per second is not a property of the player, it is a property of how many pixels the player happens to cover. Dividing the flow by the box size before thresholding is the whole fix.

Run it on your own footage

The browser game is one half. The other is a Python package that runs the same rules over a webcam or a video file, with YOLO11n or weights-free HOG detection, and writes the benchmark every number here comes from. 

git clone https://github.com/safdar-hussain1/red-light-green-light-cv.git
cd red-light-green-light-cv
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[audio,analysis,dev]"

# play against your webcam
redlight play --source 0

# referee the included footage, headless, and report
redlight play --source data/vtest.avi --headless --auto-start 10

# reproduce every number here, into a scratch file
# (exact on the package versions the README pins)
redlight benchmark --out /tmp/bench.json

# build this page from the results
redlight build-site
